# 任务、事实源和恢复政策

## 分层

- 根级 README 面向学习者；AGENTS 面向 AI。稳定规则只在 `.ai/` 维护。
- `MEMORY.md` 记录来源明确的长期偏好及稳定结论，不放每日状态。
- `2026-Winter-Exam/README.md` 只保存当前学习包的入口指针和导航，不列所有活跃任务的状态。
- 每个包 `TASK-META.json` 是 ID、类型、边界、状态、依赖、产物和验收状态的权威；包 README 不复制状态表。
- `接续与变更.md` 保存下一步及当前难点；实际表现只在 `作答与反馈.md` 和 `验收与证据.md` 记录。
- 根级 `AI-INTERACTION-PANEL.md` 是唯一 open 协作事项索引；无真实协调需求时保持空表。

## 最小交付单元和类型

一个正式学习包对应一个能独立检查的目标，可跨几次短会话完成，不按“每个单词一个包”或“每天一个包”切割。

| 类型 | 输入 | 输出与完成判据 |
| --- | --- | --- |
| `baseline` 起点观察 | 用户背景、自然短互动、真实音频 | 有来源的能力观察、未测边界和下一阶段建议；文字理解及听力证据齐备，或用户明确接受缺项后关闭；不强制摸底考试 |
| `learning-unit` 专题学习 | 一个具体理解目标、已有薄弱点 | 作答、反馈及换情境或延后复测；开工前写明小目标和判断标准，不据此宣称整个 N3 达标 |
| `exam-practice` 考试练习 | 来源明确的题组/试卷、对应音频 | 实际答案、条件、分项正确率、用时（已知时）、错误分析和后续动作；不伪造官方尺度分 |
| `project-setup` 工程维护 | 用户授权、当前文件 | 结构、链接、元数据检查结果和恢复说明；不替代教学验收 |
| `resource-build` 教学资料建设 | 授权范围、可使用的来源、材料需求 | 可追溯的资料、来源许可、处理记录、质量检查和使用边界；不把采集量当成掌握量 |

共用 [核心模板](../../2026-Winter-Exam/templates/learning-task/README.md)。按类型在现有目标和验收文件中增补字段，必要时才加 `assets/`、`events/`、`tests/` 或 `backups/`。不创建空业务材料和无用目录。熟悉内容的几分钟重遇直接记入原包，不建立另一种快捷看板。

## 生命周期

`draft` → `ready` → `active` → `review` → `closed`；需要外部条件才能继续时使用 `blocked`，恢复时写原因。状态不表达学习者优劣。

`acceptanceStatus` 使用 `not-started | partial | passed | failed | blocked`。单条验收还可为 `not-applicable`，但必须注明原因、替代口径和何时重新适用。`passed` 需要实际证据；用户接受缺项的关闭包可保持 `partial`，将明确接受的范围与来源写进 `acceptedExceptions`。不得把未知改成通过。

新建包使用递增编号和稳定英文主题名，ID 如 `JP-N3-002`；目录名不复用已关闭任务编号。填写具体输入、目标、产物、下一步和验收标准后才设为 `ready`。依赖写已有任务 ID。

教学开始前按 AGENTS 路由读文件；任务内 `skills` 目前为 `[]`，`instructions` 列出具体路径。不得用“使用相关 Skill”代替路径。字段路径统一相对于项目根目录；本地 Markdown 链接相对于所在文件。

## 一次会话的记录

在同一包内按日期和序号追加记录。保留用户原始尝试；纠正写在旁边，不覆盖原答。每段记录区分实际发生、用户自报、AI 推断和拟议安排。不知道时长就写未计时。

结束或暂停时依次更新：作答和验收证据 → 接续与变更 → 元数据时间、阶段和状态 → 必要的入口指针或协作事项。接续说明必须包含当前入口、下一步、未决事项、材料/证据路径和资源占用（无则写无）。

默认一个教师串行修改当前包。多个会话同时打开时，先核对最近更新时间；发现冲突保留两份证据并暂停相同文件写入。明确获准并行时只并行独立材料准备；用户作答、判读和状态更新串行。冲突资源是当前任务记录、入口指针和共享规则。

## 关闭和下一包

关闭前核实产物可定位、验收有实际结论、缺项已解决或有用户明确接受、证据齐全、接续可恢复、临时资源已释放。更新元数据，然后把备考入口指向下一包。关闭不删除作答与证据。

除工程初始化外，不预先创建整套待办课程。首次观察后按实际缺口创建下一个最小目标；计划需注明试行，不用未经验证的学习速度预测合格日期。

## 备份与恢复

首次初始化只在重新确认不存在的路径新增文件，无旧文件可备份。初始化清单由 `tools/initialization-manifest.json` 保存，未来更新不要重写原始清单。

已有文件进行覆盖、迁移、合并或大幅重写前，将旧版原样复制到该包的 `backups/<时间>/`；稳定规则的旧版保存在根级 `backups/<时间>/`，并记录原路径及恢复方式。普通追加学习记录不需要复制全库；元数据状态改变在接续文件留痕。Git 若以后启用，可用已确认包含相关文件的提交作恢复点；当前不假定已有 Git。

错误作答不可清除或改成正确答案。恢复文件时先保留当前版，避免丢失后续学习记录。清理优先移到废纸篓；初始化回退仅处理清单内且未被后续修改的文件，不递归删除既有 `2026-Winter-Exam` 目录。含新学习记录的文件保留并另行处理。

## 外部动作和维护范围

用户已授权本地工程初始化、日常辅导及必要记录维护，不重复要求每课或每个文件确认。报名、付费、对外发送、发布和自动提醒需要对应的具体授权。不要索取或保存准考证号、证件、账号密码等无关信息。

工程新增/移动文件、变更任务状态或规则后运行 `python3 tools/check_project.py`。普通单课追加由教师检查实际记录和接续一致性，无需为每句教学内容编写软件测试。工具检查通过仅说明结构一致，不能验证日语准确性或学习效果。
